# Self-contained Freeup Space setup

Users download an installer, click Install / Update / Repair, and open Freeup Space in a new Codex task. No user Python, pip, Git, PATH edits, or terminal commands are required. Existing Codex installation/sign-in remains a prerequisite. All scanning and cleanup continue locally with existing explicit candidate confirmation.

Ship a Windows x64 Setup.exe and macOS Apple Silicon / Intel Setup.app archives. A PyInstaller console runtime embeds Python and accepts --mcp, --cli, and --doctor. A separate windowed setup application embeds this runtime and the plugin source. Installer-owned files live under the current user's application-data directory. Each install/repair creates an immutable version directory so active processes are never overwritten. The dedicated freeup-space marketplace points at its current versioned plugin; config contains the installed runtime's absolute path, generated on the user's computer. Do not change the repository's portable source launcher.

Use Codex's supported CLI to register/install, without replacing personal marketplace entries or unrelated plugins. Detect the desktop app's bundled CLI as well as PATH; allow browsing if detection fails. Validate CLI support before mutation. Validate the runtime using synthetic temporary files and an MCP resource/handshake check; no real cleanup in setup or tests. Check installed plugin state before saying Ready. Migrate only older installs proven to originate from raviasha/Freeup_Space, after new installation succeeds. Preserve old version directories and restore prior catalog on failure.

The same installer rerun repairs or updates; download latest release through an explicit Check for updates link (no silent executable downloads). Show actionable errors, a log, and clear new-task instruction. Signing/notarization can be enabled with release credentials; unsigned builds must be described truthfully and must never bypass OS security checks.
